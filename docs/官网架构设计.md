# 若虚科技官网架构设计

更新日期：2026-11-04

状态：已完成开发、本地验证和 GitHub Pages 部署。公开仓库为 Vulpure/ifvoid；当前使用 GitHub 默认网址，自定义域名与 Cloudflare 配置待后续执行。

## 一、目标与范围

官网用于公司信息展示，展示名称为“若虚科技”，定位为人工智能服务集成商，域名为 ifvoid.cn，联系邮箱为 info@ifvoid.cn。以现有《若虚科技信息.md》为内容依据，完整展示算力、模型、应用、创意和治理五类服务及其 15 个分项。

本期提供中文、英文页面与对应语言切换。使命、愿景、价值观暂不纳入；不展示公司全称、客户类型分类、未提供的案例、客户标识、资质、业绩数字或产品价格。不建设登录、数据库、在线交易、AI 对话和留言后台。

## 二、信息架构

| 路径 | 页面及内容 |
| --- | --- |
| `/` | 中文首页：公司定位、五类服务概览、公司介绍与联系方式 |
| `/en/` | 英文首页，与中文对应 |
| `/services/compute/` | 算力服务：建设与租赁 |
| `/services/models/` | 模型服务：部署与推理、训练与微调 |
| `/services/engineering/` | 应用服务：知识问答、助手与智能体、工作流集成 |
| `/services/creation/` | 创意服务：文字、图像、音频、视频及跨媒介整合 |
| `/services/governance/` | 治理服务：组织环境渗透测试、模型评测、防护建设、展业地区合规 |
| `/en/services/{slug}/` | 五类服务的英文对应页面 |
| `/404.html` | 自定义错误页面，提供中英文首页入口 |
| `/robots.txt`、`/sitemap.xml` | 搜索引擎抓取规则与 12 个内容页的站点地图 |

所有服务正文在构建时生成 HTML，无需执行 JavaScript 才能阅读。首页卡片与菜单链接直接进入对应详情页；详情页保留其他服务入口。语言切换进入当前页面的对应译文。公司介绍与联系为首页锚点，减少只有少量内容的独立页面。

## 三、视觉与交互设计

### 1. 视觉方向

采用月白底色、深海蓝正文与科技蓝强调，辅以水色、月金和少量莲紫，形成“春江、花月、夜色”的克制意象。色彩借鉴高校视觉体系的蓝色与紫色关系，但页面文字不陈述相关背景。以大字号中文标题、清晰的英文名称和充分留白组织页面；视觉主体使用代码绘制的水纹、环形及连接结构，表达五类能力的集成，不使用虚构产品截图或采购素材。按用户 2026-11-04 的修改要求，移除主视觉中的黄色月牙及其光晕。

中文以系统字体为基础，标题搭配本机宋体后备字体，英文使用系统无衬线字体；不依赖外部字体 CDN。采用文字排版“若虚科技 / IFVOID”作为当前站点标识，不将其表述为已注册商标或已确认的英文工商名称。

### 2. 内容层级

首页首屏展示公司定位、总述与服务和邮件联系入口。服务索引使用连续编号及开放式分栏，避免重复堆叠营销卡片。详情页采用标题、完整介绍、分项服务与联系入口的固定阅读结构。

### 3. 交互规则

桌面顶部直接展示算力服务、模型服务、应用服务、创意服务、治理服务五个一级菜单，后接关于若虚、语言切换与联系入口；不设置“服务”父级下拉。中英文同步，详情页高亮当前服务。移动端提供原生可访问的折叠菜单，五类服务在其中平级排列；服务导航在没有脚本时也可使用。邮件入口使用 mailto，并提供复制邮箱按钮与成功或失败反馈。主站内容不收集访客输入。

平台入口从独立配置读取。只有填入有效 HTTPS 网址后才渲染；空配置不进入公开页面，也不使用 # 伪链接。

### 4. 响应式与无障碍

覆盖窄屏手机、平板、桌面和超宽屏。容器宽度与边距采用流式计算；在 1080px 以下将首屏与详情页改为纵向布局，在 760px 以下进一步重排服务、介绍及联系区，避免平板区间被压缩。提供跳过导航、可见焦点、语义化标题、菜单状态和复制反馈；装饰图形对辅助技术隐藏。支持 prefers-reduced-motion，不让动画影响内容阅读。

## 四、技术架构

| 部分 | 选型与职责 |
| --- | --- |
| 页面框架 | Astro，静态输出；构建工具仅用于开发与发布，不需要在线 Node.js 服务 |
| 样式与交互 | 原生 CSS 与少量 TypeScript；无前端组件框架、动画库或远程运行依赖 |
| 公司内容 | `docs/若虚科技信息.md` 为唯一人工维护的公司资料；构建时解析白名单章节与表格 |
| 站点配置 | `src/data/site.ts` 维护域名、预留平台网址与界面标签，邮箱与公司名称从资料提取 |
| 组件 | 公共布局、页头、页尾、首页、服务详情与静态 SVG 视觉组件 |
| 构建产物 | `dist/`，只含页面、资源、抓取文件与错误页；不复制内部资料或源代码目录 |
| 发布 | GitHub Actions 执行 npm ci、内容检查、构建与产物检查，再使用 Pages 官方上传和部署 Action |
| 域名与 CDN | GitHub Pages 提供源站，Cloudflare 提供 DNS、HTTPS 代理与 CDN |

内容解析应在结构缺失、服务数量或已确认名称发生不一致时明确报错。内部说明、引用文献、待补充事项和未讨论完成的品牌内容不进入网站。修改资料后重新构建即可更新中英文页面，避免再维护一份容易漂移的服务文案。

## 六、SEO、性能与发布配置

每页生成标题、描述、canonical、Open Graph、语言替代链接与结构化组织信息。生产主地址为 https://ifvoid.cn/；路径采用真实静态目录，不依赖 SPA 回退。未配置的社交账号不写入结构化数据。

首版不引入第三方统计、远程字体、地图或外部脚本，尽量降低国内访问中的额外依赖。页面主要依靠静态 HTML、CSS 和 SVG；所有交互有渐进增强或可理解的后备行为。

部署时在 GitHub 中验证域名所有权、启用 Pages 的 GitHub Actions 来源，绑定 ifvoid.cn，按 GitHub 官方记录配置 Cloudflare DNS。先确认源站自定义域名证书正常，再启用代理与 Full (strict)；统一 www 与根域名，注意 HTTPS 重定向及缓存更新。GitHub Actions 的部署任务仅在主分支推送或手动触发时运行，PR 仅构建验证。

域名接入前，当前发布入口为 https://vulpure.github.io/ifvoid/ 。工作流通过 `actions/configure-pages` 读取 Pages 配置，将 `origin` 和 `base_path` 分别作为 `SITE_ORIGIN`、`SITE_BASE_PATH` 传入构建；导航、资源、SEO 地址、404 返回入口和站点地图统一适配子路径。以后绑定 ifvoid.cn 并重新运行工作流，即可改用根域名；本地构建默认保留 ifvoid.cn 根路径。

GitHub Pages 的商业用途限制需按最终网站用途核对；当前实现保持信息展示范围。Cloudflare 免费服务不含中国大陆网络节点，国内实际访问效果需在上线后测试。静态产物可迁移至其他静态托管，不绑定付费后端。

## 七、验收与当前状态

开发验收包括：资料解析覆盖 5 类及 15 个分项；12 个中英文内容页与 404 均可访问；内部链接和语言对应有效；邮箱联系与复制反馈可用；预留平台灰色不可点击；无未确认公司事实或内部研究文字泄露；手机与桌面没有横向溢出；构建产物不包含运行时服务器。

验证采用构建与内容检查、HTTP 路由检查、浏览器实际交互和桌面／移动端视觉检查。检查结果在开发后补充，域名、邮箱与线上发布状态不由本地检查代替。
